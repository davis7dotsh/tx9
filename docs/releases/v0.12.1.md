# TX9 v0.12.1

A patch release for Hermes gateway compatibility, CI reliability, and
release-site development tooling.

## Changes

- Recognize Hermes PM's isolated Python gateway bootstrap alongside existing
  console/script entrypoints. Health checks, startup adoption, and stop/disable
  now identify the same child, including one whose supervisor has exited.
  Capture wrappers, command shims, and unrelated Python processes remain excluded.
- Browser cleanup regressions accept Linux missing-process errors when a
  process disappears while its `/proc` entry is being read. Gateway fixtures
  also clean unrecorded detached children after failures or interruption.
- Patch Miniflare's development-only Sharp dependency to 0.35.5 for
  [CVE-2026-96889](https://github.com/advisories/GHSA-wq5f-xc86-pv6w).
  The scoped override keeps the existing Wrangler and Miniflare versions and
  restores the release's required dependency-audit gate.

## Updating

Run `tx9 upgrade` for the host CLI and `tx9 upgrade <box>` for each selected
box. The gateway helper ships in the embedded guest assets and takes effect
when the box is rebuilt/upgraded. Box upgrades start the recreated container
and retain portable volumes; preserve custom image-owned Hermes checkouts
and launchers before upgrading.

A checked version bump merged to main publishes the matching tag, binaries,
and checksums through the existing release workflow. Worker deployment
remains a separate operation.

## Validation

Full `make check` and the Node 24 site gates passed, including all 14 Worker
API tests and a clean dependency audit. The patched native Sharp API passed
an SVG-to-PNG resize check. All four release targets build with CGO disabled;
Linux AMD64 reports 0.12.1, and every binary embeds the reviewed gateway helper
and existing provisioning pins.
