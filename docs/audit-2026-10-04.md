# Reliability, polish, and performance audit — 2026-10-04

This pass inspected the Go CLI, Docker/state boundary, archive and updater,
provisioning, guest supervision, log reader/capture, and public release Worker.
The work is on one reviewable branch targeting `main`.

## GitHub issue coverage

GitHub had zero open issues and zero open pull requests when inspected. The
only issue, [#24](https://github.com/davis7dotsh/tx9/issues/24), was closed and
asks for arbitrary foreground services. Its existing implementation remains;
this pass fixes a reload failure that could launch duplicate custom workers.

## Changes

| Area | Trigger and previous behavior | Result |
| --- | --- | --- |
| Command help | Flat command help returned exit 1; mount action help was missing | Help exits 0, including nested actions; malformed options still fail |
| Flag parsing | A literal leading `--` could be lost; a missing option value consumed an earlier positional argument | Preserve the separator and report the missing value |
| Argument validation | `prune <box>` silently ran global pruning; list/import ignored surplus arguments | Reject surplus positionals before operations |
| Create validation | An invalid name or resource/Executor option first failed on unavailable Docker | Validate fresh inputs before connecting |
| Image pruning | Removing an image ID with multiple tags conflicted and mixed TX9/unrelated aliases | Remove only obsolete TX9 tags; retain unrelated aliases and referenced/current images |
| List performance | Dashboard metadata was collected serially | Use four workers and preserve sorted output |
| Logs helper image | A moved/rebuilt image tag selected a different helper | Use the container's actual immutable image ID and retain inspect errors |
| Mount recreation | Mutable tags silently changed the agent image; stale list state changed whether it restarted | Retain actual image and live inspected running state; reject foreign/incomplete containers before teardown |
| Mount access | A supplemental group required by one mount removed access to another otherwise valid mount | Validate permissions using the complete supplemental group set |
| Persisted state | Trailing value whitespace was discarded; written values larger than 64 KiB became unreadable | Preserve values and read large state entries |
| Docker exec | Attachment EOF could be treated as exit 0 while Docker still reported a running command | Wait for final process status with cancellation |
| Payload extraction | Existing destinations/symlinks were overwritten; invalid archives left partial output | Create exclusively and clean only the newly created incomplete output |
| Backup staging | Failure cleanup deleted a preexisting staging file owned by another operation | Cleanup is conditional on successful exclusive creation; sync completed output before promotion |
| Backup recovery | A failed checkpoint after pause left a previously running box paused | Attempt resume after any TX9 pause attempt; preserve an already-paused box |
| Archive validation | Siblings repeatedly resolved identical immutable directory parents | Cache successful parent checks without changing validation order or link safety |
| Installer checksums | Valid binary-mode/uppercase/CRLF checksum manifests differed from the Go updater's parser | Support those forms; reject malformed and duplicate entries |
| Installer requests | Trailing origin slashes broke routing; requests could stall indefinitely | Normalize the origin and bound connection, metadata, and stalled download handling |
| Go updater | Oversized metadata was silently truncated; custom untimed clients omitted request deadlines | Explicitly reject oversized responses and add per-request metadata deadlines |
| MCP wiring | Failed readiness/credential writes still removed or replaced user MCP configuration | Stop before editing configuration; store literal tokens atomically and privately |
| Gateway/Executor policy | Queued startup could ignore a newly written pause/disable marker; stop could miss an in-flight startup | Recheck policy under the startup lock and serialize stop with startup |
| Custom service reload | A failed stop still launched a replacement and replaced the ownership record | Keep the previous identity and report failure without launching a duplicate |
| Log history | Rotated-only histories disappeared when the active file was absent | Discover retained rotations for agent, Executor, services, and Hermes; suppress raw duplicates |
| Log time filtering | Space-separated Python timestamps were interpreted as midnight | Preserve time, fractional seconds, and offsets for `--since` |
| Malformed log data | Huge timestamps/timezone overflow and unusual rotation suffixes crashed reads; native NaN/Infinity produced invalid JSON | Fall back safely, report invalid duration input cleanly, and emit JSON null for nonfinite values |
| Log capture | A FIFO destination could hang capture forever | Reject nonregular destinations without blocking; keep child output and exit status |
| Log query performance | All historical events were redacted before tail selection; grep serialization ran without a grep filter | Select retained events before redaction and serialize only for grep |
| Browser provisioning | A candidate replaced working binaries before dependency and navigation checks | Smoke-test the staged pair before promotion |
| Executor repair | A surviving broken launcher or failed version probe aborted/skipped repair | Reinstall when the version probe is unsuccessful or invalid |
| Cached image assets | Repeated recursive chown copied more than 1.7 GB of unchanged Hermes code/dependencies into an overlay layer | Change only ownership mismatches, including group mismatches, without following symlink targets |
| Linux release compatibility | Native CGO builds depended on a glibc loader and failed on a supported musl-based Linux host | Release builds disable CGO; both Linux binaries are static and the native one runs under musl |
| Hermes fresh provisioning | Upstream main's new PM layout no longer matches TX9's image-owned checkout/venv contract | Pin the official installer and source to published stable v2026.9.24, verify the installer digest, force the exact checkout, and protect managed options |
| Guest status | Restored `/data` is intentionally not enumerable by the agent; `du` emitted a misleading partial 4 KiB total on error | Report usage as unavailable when the measurement fails; keep successful measurements |
| Browser health | Relative binary/fixture overrides became invalid after the probe changed working directory | Resolve invocation paths before entering its private probe directory |
| Hermes inspection | Repeated recursive scans counted backups/caches and duplicate nested inventory, and attempted to parse stale cache JSON | Walk the active tree once, prune excluded directories, ignore symlink files, and report nonobject gateway state as invalid |
| Embedded asset validation | The test packed the entire working tree, including node_modules and local files | Test the actual embedded build context from the main package |

The source patches stay at their owning boundaries. New regressions exercise
failure cleanup, Docker protocol behavior, lifecycle locks, query/export
selection, and real subprocess behavior in disposable fixtures.

## Hosted review follow-up

Macroscope found an omitted valid ISO offset form: `+01`/`-01` prefixes
were stripped from raw timestamps even though the underlying ISO parser
supports them. For example, `2026-10-04T14:00:00+01` became 14:00 UTC instead
of 13:00 UTC, affecting `--since` and newest-event ordering. The prefix
matcher now retains hour-only offsets alongside compact and colon-separated
minute offsets. A regression failed before the fix and covers both signs,
query cutoffs, query tails, and exported tails.

## Distribution and operational scope

Hermes's stable pin is commit `f97608f178d1ffeca59860195ab7da295f7c8e5f`.
The immutable official installer is SHA-256
`2017ddf0cc7bc6cfb70d40dc9fba1d916f47dbcccf5fe73bdee2cf93a11262af`.
Both script and checkout must be pinned: a pinned installer alone still
clones main, and this installer ignores an ancestor commit unless
`--force-commit` is supplied. Root auto-detection retains its FHS/shared Python
layout. Existing usable installations retain their current version.

An explicit `hermes update` remains an independently operated upstream
update and may adopt its new PM architecture; that migration is outside
this image compatibility fix. ARM64 provisioning and the live Hermes
updater migration are not proven by Linux AMD64 or hermetic tests.

Guest fixes require an image rebuild and box upgrade. Worker changes require
a Worker deployment; CLI fixes require installing a binary from this branch.
No production Worker deployment, release publication, or existing live box
upgrade is part of this pass. The PR remains open for review.
