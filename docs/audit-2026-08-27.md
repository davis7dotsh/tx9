# tx9 audit, 2026-08-27

The audit started at `c9de8d053e80ae3c4f0e1cd1bce2510ad4944a76` and covered
the host CLI, Docker lifecycle, guest provisioning and supervision, archive
handling, logs, release Worker, dependencies, and CI. Implementation reviews
ran separately from independent security/correctness and architecture/design
reviews. Tests used synthetic credentials and isolated fixtures. No running
box or real credential store was used as an attack target.

The largest unresolved issue is the Executor authorization model. The agent
receives an administrator token, so separate containers do not keep
Executor-managed credentials confidential from that agent. The
[security model](security-model.md) traces this to upstream Executor source
and explains what a restricted agent identity would require.

## Security and data preservation

| Problem | Change and reason |
| --- | --- |
| Tokens appeared in child process arguments. | Interactive Docker entry uses an environment variable name instead of its value in argv. Executor starts from a private auth file instead of a token argument. The token remains accessible to trusted host/container administrators. |
| SQLite resolved an apparently safe file-descriptor path back through mutable directories. | The log reader now queries private database/WAL snapshots made from validated regular-file descriptors. It does not let SQLite reopen the original path. |
| Special files could block log reads. | Nonblocking, no-follow file opens reject FIFOs and other nonregular files before reading. |
| Quoted credential values could be only partly redacted. | Redaction consumes complete quoted values, including escaped and multiword content, across capture chunks. It is still best effort. |
| Log helpers could access both durable volumes and the network. | Temporary restore/log helpers now have no network and cannot gain privileges. Cleanup removes temporary containers and anonymous volumes even after cancellation. |
| Docker attachment copies could outlive a failed operation. | Cancellation closes attachments, and helper returns wait for input/output copies before the caller can close its files. Caller-provided readers and writers must still finish their own blocking operations. |
| Plaintext backup intermediates and GPG password handling exposed unnecessary state. | Temporary backup directories are private, outputs use exclusive mode-0600 creation, and GPG reads passwords from a dedicated descriptor. The child environment excludes `TX9_PASSWORD`. |
| Malformed outer archives or long link chains consumed excessive work or created ambiguous input. | Metadata is bounded and decoded strictly, outer members must match the format exactly, and link resolution has a fixed depth limit. Valid archive payload size is not capped. |
| A reused name could overwrite a token or attach unrelated Docker storage. | Fresh create/import refuses existing derived resources before writing a token. Reuse checks Docker ownership labels. |
| Deletion could remove some resources before discovering a foreign sibling. | Destroy inspects all derived and discovered resources before its first deletion. Any ownership or inspection failure leaves resources and cached credentials unchanged. Container/network deletion uses inspected IDs. |
| Install/update staging used predictable paths. | Updates use private, unique sibling staging and atomic replacement. Failed checksum verification preserves the installed binary. Custom builds and numerical downgrades require `--force`. |

These checks protect against malformed input, accidents, and the specific
cross-volume log-reader race. Ownership labels and host locks are not an
authorization boundary against another Docker administrator.

## Runtime, architecture, and performance

- The overview inspects each container once, with at most four concurrent
  workers, while one volume-usage query runs independently. Slow disk
  accounting no longer serializes all container metadata. Warning order
  remains deterministic, and absent usage data stays unknown rather than
  appearing as zero.
- State pruning takes the box lock and rechecks Docker resources before
  deleting a token cache. Orphaned containers, volumes, networks, and Docker
  inspection failures preserve the state needed for recovery.
- Doctor probes the configured published address, including IPv6, instead of
  assuming IPv4 loopback. Cancelled checks stop waiting for retries.
- Service shutdown kills remaining members of the supervised process group,
  including descendants that ignore termination after closing stdout.
  Detached processes that create a different session remain outside this
  process-group contract.
- Runtime initialization, pause/resume, and cutover checks propagate failures
  instead of printing success after an earlier command failed.
- Log queries skip unrelated source histories before opening them and use the
  canonical Hermes database without recursively scanning its entire tree.
  SQLite URI construction also handles paths containing `#` or `?` correctly.
- The Go check no longer compiles every package twice through a separate
  `go build` and `go test`; tests already compile the full package graph.

These changes keep the existing CLI, guest scripts, and two-container model.
A new orchestration framework, remote control service, or replacement process
supervisor was not needed to fix the demonstrated failures.

## Release API

The Worker validates release versions and asset names before accessing R2.
It streams versioned downloads with immutable caching, uses metadata-only
HEAD requests, and supports conditional downloads that return 304 without
transferring the object body. Latest pointers, redirects, and installer
responses remain uncached so clients discover new releases.

Eight tests execute the actual Worker source with an in-memory R2 fixture.
They cover routes, malformed requests and stored pointers, caching,
conditional requests, missing objects, and installer/source consistency.
They do not exercise a deployed Cloudflare Worker.

## Dependencies and CI

The CLI now requires Go 1.26.7 and updates the dependencies compiled into the
CLI and its tests. The site uses locked TypeScript 7.0.2 and Wrangler 4.127.0,
with explicit formatting, lint, and test commands. CI installs locked npm
packages with lifecycle scripts disabled, pins actions to commits, verifies
the ShellCheck download, and checks every PR base branch so stacked changes
receive checks. Release upload uses the reviewed local Wrangler binary
instead of installing a floating package with Cloudflare credentials present.

The npm audit moved from four high-severity tooling findings to zero. The Go
scan no longer reports the baseline standard-library findings. Five Docker
module advisories remain, covering daemon behavior and broad module matches.
This is not a clean Go vulnerability scan and does not prove the host Docker
daemon is patched. See the [dependency audit](dependency-audit-2026-08-27.md)
for versions, primary sources, advisory disposition, and reproduction commands.

Provisioned agent tools still follow upstream channels or retain existing
installs. Cached images, running boxes, the host kernel, and the Docker daemon
were not upgraded. No image build, release, or Worker deployment was performed.

## Validation evidence

- Shell syntax, ShellCheck, static contracts, guest regression suites, Go
  formatting, vet, unit tests, and race tests passed during integration.
- Temporary Docker helpers were tested with the already installed
  `ubuntu:24.04` image. Tests checked offline networking, stream round trips,
  cancellation, and cleanup without mounting real box volumes.
- A synthetic mutable-directory SQLite race produced a private Executor row
  before the snapshot fix. After the fix, 10,000 attempts produced no private
  rows; deterministic regressions cover the unsafe path reopening separately.
- Ten mixed-ownership deletion cases and seven helper I/O lifetime cases
  failed against the preceding implementations and passed after their fixes.
- A local log-query benchmark with 17.7 MB of irrelevant Hermes histories
  dropped from a median 0.6414 seconds to 0.0482 seconds over three runs.
  This measures a synthetic source-filtering case, not production latency.
- A fresh npm install with scripts disabled passed type checking, formatting,
  lint, all eight Worker tests, and audit. The Worker tests also passed on the
  declared minimum Node version, 22.18.0.
- Actionlint passed with only the existing Depot runner-name and queue
  extensions excluded. Hosted checks are recorded on the pull requests.

An early reviewer ran the original `make check` target before its separate
`go build` step was removed. That compiled the CLI despite the instruction to
ask before building. Later checks used the updated target. No image build or
deployment occurred.

The security report is a source review with targeted executable proofs, not a
formal penetration test or a guarantee that all credentials remain secret.
Unbounded valid archives, large logs/snapshots, and live database writes can
still cause resource exhaustion or read failures. Log redaction cannot
recognize every secret or encoding.

## Decisions left open

| Decision | Recommended direction and consequence |
| --- | --- |
| Agent permission to manage Executor | Default to restricted tool access under a separate identity. Keep management and approval authority with the operator. This removes the agent's ability to configure arbitrary integrations and requires a proxy/tool allowlist that also blocks alternate network routes. |
| Published endpoints and tokens | Make private HTTPS exposure the normal setup and add explicit token rotation. The current dynamic HTTP endpoint and reusable token URL remain supported, so changing defaults affects onboarding and remote access. |
| Reproducible images | Publish tested images with pinned tools and digests on a scheduled update cadence. This adds image release operations and a policy for when users receive security fixes. |
| Disk and history limits | Define retention and storage budgets before adding enforced quotas or deleting native histories. Current volume budgets are advisory, and native histories may be valuable user data. |
| Executor portability | Decide whether Executor credentials and configuration should travel through a separately encrypted backup. Current agent backups intentionally omit that volume. |

The restricted Executor identity is the first decision to resolve before
using these boxes with credentials the agent must not be able to read.
